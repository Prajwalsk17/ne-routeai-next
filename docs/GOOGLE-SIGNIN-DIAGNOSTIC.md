## 2. Deep Root Cause Analysis

### What Happened
When clicking "Continue with Google", the Firebase Client SDK (`signInWithPopup(auth, provider)`) dynamically executes two operations:
1. Injects a script tag: `<script src="https://apis.google.com/js/api.js?onload=__iframefcb..."></script>`
2. Creates an embedded communication iframe pointing to: `https://ne-routeai-next.firebaseapp.com/__/auth/iframe`

### The Interception
The application's Next.js security middleware (`src/middleware.ts`) sets a strict `Content-Security-Policy` header generated by `getProductionSecurityHeaders()` in `src/lib/security/headers.ts`.

Prior to this fix, the CSP header was configured as:
```http
content-security-policy: default-src 'self'; script-src 'self' 'unsafe-inline' 'unsafe-eval' https://cdn.jsdelivr.net https://unpkg.com; ...
```

1. **`script-src` Violation**: Google's API script `https://apis.google.com/js/api.js` was NOT in the whitelist. The browser immediately aborted loading with the exact console error:
   ```
   [BROWSER LOG error] Loading the script 'https://apis.google.com/js/api.js?onload=__iframefcb...' 
   violates the following Content Security Policy directive: "script-src 'self' 'unsafe-inline' 'unsafe-eval' https://cdn.jsdelivr.net https://unpkg.com".
   ```
2. **`frame-src` Missing**: Because `frame-src` was not defined, it fell back to `default-src 'self'`, blocking `https://*.firebaseapp.com/__/auth/iframe` and `https://accounts.google.com`.
3. **The Firebase SDK's Reaction**: The browser fired an `<script onerror="Event">` event. Firebase caught this failed network/DOM event and raised `auth/internal-error` with `customData: Event`.
4. **The False Diagnosis**: Previous reports mistook `auth/internal-error` for a Firebase Console misconfiguration ("Google provider not enabled or missing support email"). In reality, the Firebase project `ne-routeai-next` was already properly configured; the app was simply blocking Google's scripts from executing.

## 3. Files Changed & Fixes Applied

### 1. `src/lib/security/headers.ts`
Updated `buildContentSecurityPolicy()` to whitelist Firebase Authentication and Google OAuth endpoints:
- **`script-src`**: Added `https://apis.google.com`, `https://www.gstatic.com`, `https://*.firebaseapp.com`, `https://*.googleapis.com`.
- **`frame-src`**: Added `frame-src 'self' https://*.firebaseapp.com https://accounts.google.com https://*.google.com`.
- **`connect-src`**: Added `https://*.firebaseio.com`, `https://*.firebaseapp.com`, `https://identitytoolkit.googleapis.com`, `https://securetoken.googleapis.com`.
- **`img-src`**: Added `https://*.googleusercontent.com`, `https://*.gstatic.com`.

### 2. `src/lib/auth/auth-errors.ts`
- Aligned `auth/internal-error` in Google context with test suite expectations.
- Enhanced `safeLogAuthError` to record `code`, `message`, and `customData`.

### 3. `src/app/login/page.tsx`
- Preserved all existing authentication methods (Email/Password, Phone OTP, Country Selector +91, E.164 normalization, password toggle).
- Surfaced the real Firebase error category in development mode: `[${errCode}] ${readable}` so developer never sees a swallowed or generic error.
- Ensured `signInWithGoogle` directly calls `signInWithPopup(auth, provider)` using GoogleAuthProvider.

### 4. `src/app/signup/page.tsx`
- Surfaced real Firebase error category in development mode: `[${errCode}] ${readable}`.
- Added comprehensive error logging for `error.code`, `error.message`, and `error.customData`.
